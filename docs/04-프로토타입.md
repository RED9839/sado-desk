# 사도 데스크 프로토타입 — 크레페 미니미 데스크탑 마스코트 (v0.1~)

> 2026-09-11 · 위치 `prototype/` · 실행 `prototype\run.cmd`

## 무엇을 만들었나
게임에서 추출한 **미니미 Spine 데이터를 공식 spine-ts 4.1 런타임으로 그대로 재생**하는 Electron 데스크탑 펫. 파서를 직접 짜지 않고 런타임을 썼기 때문에 77개 애니 전부·418 캐릭터 스킨 전부가 그냥 나온다.

| 검증된 것 | 방법 |
|---|---|
| 작업표시줄 위 바닥에 서서 폴짝폴짝 이동(`Idle2_1`), 랜덤 대기 동작, 큰 점프(`Jump*`), 하늘에서 등장(`Spawn1/2`) | `--log-pos` 로그, 스크린샷 (게임 위에 정상 표시) |
| 클릭 → 반응 애니 + 터치 보이스 재생 | `--selftest` |
| 드래그 → 던지기(속도 추적) → 벽/천장 튕김 → 착지(`Idle2_3`) | `--selftest` |
| 캐릭터 밖은 클릭 통과, 위에선 잡기 커서 | `--selftest` + 실사용 |
| 우클릭 HTML 메뉴: 행동 77개 재생, 스킨 418개 검색/교체, 크기, 종료 | `--selftest` + 스크린샷 |

## 기술 결정과 이유
- **Electron (Node 24)**: 이 PC에 JDK가 없음. 그리고 spine-ts는 Esoteric 공식 런타임이라 4.1 바이너리(.skel)를 무수정 로드. Java로 가면 spine-libgdx를 붙여야 하는데 Shimeji 엔진(Swing/JNA)과 렌더 파이프라인이 달라 통합 비용이 큼. Little LUMI도 정원 앱에 Electron을 이미 씀.
- **창 하나로 작업영역 전체 덮기 + `setIgnoreMouseEvents(true,{forward:true})`**: 마우스가 캐릭터 bounds 위일 때만 클릭을 받음. 시메지처럼 캐릭터마다 창을 움직이는 방식보다 단순하고 떨림 없음.
- **`focusable:false`**: 캐릭터를 클릭해도 게임/작업 창의 포커스를 뺏지 않음. 대신 **네이티브 컨텍스트 메뉴가 안 뜨는** 문제 → 메뉴를 HTML로 직접 그림(트레이 메뉴는 네이티브 유지).
- **미니미 슬롯 중 `Background/테두리/대성공`은 매 프레임 숨김**: 게임 UI용 프레임/뱃지.

## 발견한 버그(수정됨)
- 루트 본 회전을 `+=`로 누적 → setup 기준 덮어쓰기로 변경
- 애니 교체 직후 **이전 트랙 엔트리의 지연 `complete` 이벤트**가 상태머신을 흔듦 → `entry === state.getCurrent(0)` 검사
- Electron 실행 시 VS Code 터미널의 `ELECTRON_RUN_AS_NODE=1` 때문에 `require("electron")`이 경로 문자열을 반환 → `run.cmd`에서 해제
- preload가 기본 sandbox라 `fs` 불가 → `sandbox:false`
