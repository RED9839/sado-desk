# 트릭컬 리바이브 클라이언트 분석 (뮤뮤 앱플레이어)

> 분석일: 2026-09-11
> 대상: MuMu Player Global 12 (Android 12) 내 `com.epidgames.trickcalrevive`
> 방법: `MuMuManager.exe control -v 0 launch` → `adb connect 127.0.0.1:16384` → 파일 목록 조회 + 샘플 3~4개 pull → UnityPy로 내용 확인. **게임은 실행하지 않았고**, 분석 후 VM 종료.

---

## 1. 한 줄 요약

**Unity 6 (6000.3.13f1) + IL2CPP 게임. 캐릭터는 전부 Spine 4.1.08 스켈레톤 애니메이션이며, 다운로드 리소스는 암호화 없는 Unity AssetBundle(UnityFS)로 `/sdcard/Android/data/.../files/Packages/` 아래 6.8GB.**

→ 데스크탑 마스코트에 필요한 "SD 전투 캐릭터"(Idle/Move/Attack/Victory…)와 "로비 스탠딩"(Idle/Happy/Pat/Tickle/Sleep…) 애니메이션 데이터 구조를 확인함.
→ 단, 리소스 추출·재배포는 저작권 문제. **구조/규격 파악용**으로만 사용하고 실제 배포 에셋은 별도 확보 필요.

## 4. Spine 데이터 상세 (★ 핵심)

### 4.1 폴더
```
spine/
├─ standing/        500 폴더 (스킨 포함) / 213 기본 캐릭터  ← 로비 스탠딩 (대형, 터치 상호작용)
├─ ingame/
│   ├─ hero/        417 폴더 / 143 기본 캐릭터              ← SD 전투 캐릭터 (★ 마스코트 후보)
│   ├─ minion/ monster/ effect/ bg/ ui/ screendirection/
├─ minimi/          미니미 (더 작은 SD, minimi/minimi_2/minimi_3 + neti_minimi)
├─ outgame/         53 폴더: pet, myhome_npc, garden, dialogue, gacha(capsulemachine), tricdice…
├─ arthall/ breadcrumb/
└─ defaultsetting/  Spine 셰이더 머티리얼 (default/additive/multiply/grayscale/tintblack…)
```

폴더명 규칙: `{캐릭터명}`, `{캐릭터명}skin{N}`, `{캐릭터명}r41` (리메이크/변형) — 예: `alice, aliceskin1~4, ameliar41, ashurmagi`

### 4.2 캐릭터 1개당 파일 (예: `spine/ingame/hero/alice/`)
| 파일 | 크기 | AssetBundle 내용 |
|---|---|---|
| `alice` | 84KB | `Texture2D "Alice"` 1024×308, TextureFormat 50 (**ASTC 6x6**) |
| `alice.atlas` | 3.5KB | `TextAsset "Alice.atlas"` — Spine 아틀라스 텍스트 (`pma:true`, `scale:0.5`) |
| `alice.skel` | 244KB | `TextAsset "Alice.skel"` — **Spine 4.1.08 바이너리** (실제 560KB) |
| `alice_atlas` | 2KB | `SpineAtlasAsset` MonoBehaviour |
| `alice_material` | 35KB | Material |
| `alice_skeletondata` | 2.7KB | `SkeletonDataAsset` MonoBehaviour |

스탠딩(`spine/standing/alice/`)도 동일 구성, 텍스처/skel이 2~3배 큼 (`alice.skel` 578KB).

### 4.3 애니메이션 이름 (skel 문자열 추출)

### 4.4 텍스처 확인
- 샘플 `alice_ingame.png` 추출 성공 (UnityPy → ASTC 디코드 → PNG). 파츠 분해된 SD 스프라이트시트 (머리·눈·입·팔·카드 등).
- 아틀라스 `scale:0.5` → 원본 제작 해상도의 절반으로 패킹됨. 스탠딩은 더 고해상.

## 7. 추출 도구 검증
```python
import UnityPy
env = UnityPy.load("alice.skel")          # UnityFS 그대로 로드됨 (암호화 X)
for o in env.objects:
    if o.type.name == "TextAsset":  raw = o.read().m_Script   # Spine 바이너리
    if o.type.name == "Texture2D":  o.read().image.save("x.png")  # ASTC 디코드 OK
```
- 필요 패키지: `pip install UnityPy` (texture2ddecoder 포함)
- adb pull 시 Git Bash 경로 변환 주의: `MSYS_NO_PATHCONV=1`

## 8. 트릭컬 마스코트 설계에 미치는 영향

### 캐릭터 소스 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `ingame/hero` SD Spine 직접 렌더 | Idle/Move/Attack/Victory가 이미 있음. 표정 파츠 교체 가능. 143명+스킨 | Java 시메지 엔진에 Spine 런타임(spine-libgdx 등) 통합 필요. **게임 리소스 사용 = 저작권 위험** |
| B. `standing` Spine 직접 렌더 | Pat/Tickle/Touch/Sleep/Happy 등 상호작용 세트 완비 | 크기가 커서(로비용) 데스크탑엔 부담. 걷기(Move) 없음. 저작권 동일 |
| C. Spine → PNG 프레임 굽기 → 시메지 규격(192×192) | 엔진 무수정. 루미와 동일 파이프라인 | 프레임 수↑ 용량↑, 회전/미러 제약. 저작권 동일 |
| **D. 자체 제작 SD 도트/일러스트** | 저작권 깨끗. 스팀 배포 가능성 | 제작 공수. 캐릭터 수 제한 |

**권장**: 개인용 프로토타입은 A 또는 C로 빠르게 만들어 감 잡고, 배포용은 D(직접 그린 에셋) 또는 에피드게임즈 2차 창작 가이드라인 확인 후 결정. 엔진은 어차피 시메지 fork라 에셋만 갈아끼우는 구조로 만들면 됨.

### 트릭컬 고유 기능 아이디어 (루미 대응)
- 크레딧 드랍 → **엘드/별사탕/사도 카드** 드랍
- 부탁하기 기본 항목: 뮤뮤로 트릭컬 실행 (`MuMuManager.exe control -v 0 app launch -pkg com.epidgames.trickcalrevive`), 공식 카페/위키
- 호감도 → 트릭컬의 **사도 호감도(사도 키우기)** 컨셉 그대로 차용 가능
- 혼잣말 → 성격(순수/활발/냉정/우울/광기) 태그로 분리
- 멀티 캐릭터 → 성격 궁합에 따라 대화 반응 다르게
