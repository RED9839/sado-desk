# 사도 데스크 프로토타입 — 크레페 미니미 데스크탑 마스코트 (v0.1~)

> 2026-09-11 · 위치 `prototype/` · 실행 `prototype\run.cmd`

## 무엇을 만들었나
게임에서 추출한 **미니미 Spine 데이터를 공식 spine-ts 4.1 런타임으로 그대로 재생**하는 Electron 데스크탑 펫. 파서를 직접 짜지 않고 런타임을 썼기 때문에 77개 애니 전부·418 캐릭터 스킨 전부가 그냥 나온다.

| 검증된 것 | 방법 |
|---|---|
| 작업표시줄 위 바닥에 서서 폴짝폴짝 이동(`Idle2_1`), 랜덤 대기 동작, 큰 점프(`Jump*`), 하늘에서 등장(`Spawn1/2`) | `--log-pos` 로그, 스크린샷 (게임 위에 정상 표시) |
| 클릭 → 반응 애니 + 터치 보이스 재생 | `--selftest` |
| 드래그 → 던지기(속도 추적) → 벽/천장 튕김 → 착지(`Idle2_3`) | `--selftest` |
| 캐릭터 밖은 클릭 통과, 위에선 잡기 커서 | `--selftest` + 실사용 |
| 우클릭 HTML 메뉴: 행동 77개 재생, 스킨 418개 검색/교체, 크기, 종료 | `--selftest` + 스크린샷 |

## 기술 결정과 이유
- **Electron (Node 24)**: 이 PC에 JDK가 없음. 그리고 spine-ts는 Esoteric 공식 런타임이라 4.1 바이너리(.skel)를 무수정 로드. Java로 가면 spine-libgdx를 붙여야 하는데 Shimeji 엔진(Swing/JNA)과 렌더 파이프라인이 달라 통합 비용이 큼. Little LUMI도 정원 앱에 Electron을 이미 씀.
- **창 하나로 작업영역 전체 덮기 + `setIgnoreMouseEvents(true,{forward:true})`**: 마우스가 캐릭터 bounds 위일 때만 클릭을 받음. 시메지처럼 캐릭터마다 창을 움직이는 방식보다 단순하고 떨림 없음.
- **`focusable:false`**: 캐릭터를 클릭해도 게임/작업 창의 포커스를 뺏지 않음. 대신 **네이티브 컨텍스트 메뉴가 안 뜨는** 문제 → 메뉴를 HTML로 직접 그림(트레이 메뉴는 네이티브 유지).
- **미니미 슬롯 중 `Background/테두리/대성공`은 매 프레임 숨김**: 게임 UI용 프레임/뱃지.

## 발견한 버그(수정됨)
- 루트 본 회전을 `+=`로 누적 → setup 기준 덮어쓰기로 변경
- 애니 교체 직후 **이전 트랙 엔트리의 지연 `complete` 이벤트**가 상태머신을 흔듦 → `entry === state.getCurrent(0)` 검사
- Electron 실행 시 VS Code 터미널의 `ELECTRON_RUN_AS_NODE=1` 때문에 `require("electron")`이 경로 문자열을 반환 → `run.cmd`에서 해제
- preload가 기본 sandbox라 `fs` 불가 → `sandbox:false`

### v0.11.8 — 첫 실행 크래시 수정(중요), 말풍선 XSS 차단, preload 경로 제한
- **새 PC 첫 실행에서 추출 직후 앱이 죽던 문제**: `Cannot read properties of undefined (reading 'multiMonitor')`. 추출은 정상이었고(로그 `[exit 0]`), 원인은 설정 병합이었다. 설정 파일이 없으면 `loadSettings()`가 v1 이관 분기를 타면서 `{sound: undefined, display: undefined}`를 만들고, `deepMerge`가 그 `undefined`로 기본값을 덮어써 `settings.global.display`가 사라진다 → 추출 종료 핸들러의 `startMascot()` → `geometry()`에서 죽음. 이 PC에는 이미 정상 `settings.json`이 있어 드러나지 않았고, **새로 설치하는 모든 사용자가 겪던 문제**
  - `deepMerge`가 값이 `undefined`인 키를 건너뛰도록, v1 이관 때 `undefined` 키를 지우도록, `geometry()`는 설정이 깨져 있어도 기본값으로 동작하도록 세 겹으로 막음. 설정 파일 없는 userData로 실행해 재현·수정 확인

- `preload.js`의 `readBytes/readText`에 경로 제한이 없어 창 하나라도 주입되면 임의 파일 읽기로 이어졌다 → 앱 폴더·`data`·에셋 폴더 아래만 허용(`roots:get` 동기 IPC)

### v0.11.11 — 먼저 말 걸기가 혼잣말을 여러 번 하던 문제
사용자가 "가끔 혼잣말을 세 번 연속으로 한다"고 알려 왔다. 원인이 하나가 아니라 셋이 겹쳐 있었다.

**(1) 대화창이 말풍선을 두 개 만들었다** — `renderer/chat.js`
- 먼저 말 걸 때도 답은 `chat:token` 으로 흘러들어와 말풍선이 이미 하나 만들어진다. 그런데 `chat:say` 가 그것을 쓰지 않고 `add()` 로 **하나 더** 붙였다
- 남은 말풍선은 `typing` 클래스가 안 벗겨지고 `[감정:행복]` 태그가 그대로 보였다(태그는 `parseEmotion` 이 마지막에 뗀다). `resize()` 도 안 불러 창 높이가 어긋났다
- 스트리밍으로 만든 말풍선을 마무리하도록 고쳤다. 오프스크린으로 같은 IPC 순서를 흘려 확인: **2개 → 1개**

**(2) 모델이 먼저 말을 거는 대신 제 혼잣말에 대답했다** — `main.js`·`ai.js`
- `chatTurn` 은 사용자가 보낸 말이 없으면 기록만 넘겼다. 기록 끝이 assistant 라 `normalizeMessages` 가 `"(계속)"` 을 붙이고, 모델은 이어 말하기로 알아들었다
- `"(사용자가 조용히 있다)"` 는 **기록이 비었을 때만** 쓰이고 있었다. extra 의 "네가 먼저 말을 걸어라" 와 아귀가 안 맞았다
- 기록이 있든 없든 침묵 한 줄을 붙이도록 고쳤다

**(3) 화면을 본 척했다** — `ai.js`
- 스크린샷 규칙이 첨부 여부와 상관없이 늘 프롬프트에 있었다. 화면 보기가 꺼져 있는데 "화면 보니 코딩하시네요"(버터), "화면 보니 코딩에 집중하고 있네"(셀리네) 같은 답이 나왔다
- `opts.image` 로 갈라, 없으면 "사용자의 화면은 보이지 않는다. 아는 척하지 말고 화면 이야기를 먼저 꺼내지 않는다" 를 넣는다

**함께 고친 것**
- 답이 회차마다 길어졌다. 모델이 기록에 쌓인 제 지난 답의 길이를 따라간다 → 먼저 말 걸 때 참고 기록을 **최근 두 마디**로 줄이고, 프롬프트에 "100자 안팎"·"60자 안팎"을 넣었다
- 감정 태그를 `[]` 말고 `{}`·`()` 로 쓰거나 마크다운에 싸서 오면(`[*감정:기본]*`, `{감정:행복}`) 못 알아보고 **말풍선에 그대로 남았다**. 괄호 세 종류와 별표·밑줄을 받도록 고쳤다
- 사전에 없는 감정 낱말 17개를 받아 준다(희망·호기심·결의·피로·공상 …). 짝 잃은 `**` 도 걷어낸다
- `Ai.status()` 를 await 하는 동안 다음 1분 타이머가 겹쳐 들어올 수 있었다 → `proactiveBusy` 로 막는다

**실측 (138명 × 3회 = 414건, ollama exaone3.5:7.8b)**

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 120자 초과 | 186건 (45%) | **100건 (24%)** |
| 평균 길이 | 123자 | **97자** |
| 화면을 본 척 | 13건 | **0건** |
| 줄바꿈 섞임 | 23건 | **0건** |
| 사전에 없는 태그 | 16건 | 9건 |
| 외국어 섞임 | 8건 | 4건 |
| 문장 잘림 | 3건 | 1건 |

회차별 평균 길이 79 → 119 → 171자였던 것이 **69 → 97 → 127자**로. 여전히 회차가 갈수록 길어지지만 기울기가 눕는다.

**남은 것**: 120자 초과 24%, 외국어 혼입 4건(`hehe`·`Perfect`·한자). 작은 모델이 규칙을 흘리는 것이라 프롬프트로는 여기까지다. 재는 도구는 `tools/proactive-test.js`.
